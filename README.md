# tube-auto

15〜20分の日本語・科学解説動画を自動で作って投稿するパイプライン。
一次ソース収集 → 台本 → ナレーション → 素材 → 図解 → 合成 → 人間レビュー → 投稿 → 公開 →
計測 → 実績を企画へ戻す、までを1本の CLI で回します。

> リポジトリ名は `Youtube-Shorts-Auto` のままですが、**ショートは作りません。**
> 理由は下の「なぜ長尺なのか」にあります。

## これは何を狙っているのか

**コストを差し引いて月30,000円。生成予算は月5,000円以内。**

最大の関門は再生数ではなく**収益化ゲート（直近12ヶ月で総再生時間4,000時間）**です。
実測から逆算すると1本あたり約47時間、つまり**約85本**。ランプアップを含めて約3.5ヶ月かかります。

### なぜ長尺なのか

ショートを捨てたのは好みの問題ではありません。

| | 長尺 | ショート |
|---|---|---|
| RPM（実測・日本の知的雑学） | **¥561.6** | ¥4.5〜15 |
| 粗収益¥35,000に必要な月間再生数 | 6〜12万回 | **233〜778万回** |
| 収益化ゲートへの寄与 | 総再生時間にカウント | **カウントされない** |

**ショートの視聴時間は4,000時間に一切カウントされません。**
同ジャンルの実在の失敗例は、32本中3割をショートに使い、有効再生時間1,500時間で収益ゼロ。
同ジャンルの成功例は91本すべて長尺で、登録者5,000人・月¥77,047。差はここでした。

### 撤退基準はコードに入っている

`tube-auto report` が判断材料を出します。勘で続けないための装置です。

| 時点 | 基準 | 満たさなければ |
|---|---|---|
| 1本目 | 全編試聴して「自分が見たいと思うか」 | 設計を見直す |
| 1ヶ月 | 累計16本 / 視聴維持率30%以上 / 実測RPM ¥150以上 | 台本・冒頭5秒・サムネを見直す |
| 3.5ヶ月 | 有効再生時間が4,000時間の50%以上 | **中止を検討** |
| 収益化後2ヶ月 | 月¥10,000以上 | 中止 |
| 随時 | 累計コスト ¥30,000 | 見直し |

`report` は**証拠が足りないうちは判定を出しません**。腕ごとのサンプルが
`min_samples_before_weighting` に届くまで「判定不能」と言い続けます。

## セットアップ

```bash
sudo apt-get install -y ffmpeg fonts-noto-cjk   # 合成とCJK字幕に必須
pip install -e ".[dev,review]"
cp .env.example .env                            # ANTHROPIC_API_KEY を記入
gcloud auth application-default login           # ナレーション（TTSはキーではなくADC認証）
tube-auto init
tube-auto doctor                                # 何が足りないか一覧で出る
```

`tube-auto doctor` は、ツール・APIキー・ADC・OAuthトークン・設定の整合・今月の支出・価格表の鮮度・
**TTS無料枠の消費率**・NASA APIの到達性・止まっている工程を一度に診断します。
**キーを入れる前でも動く**ので、まずこれを実行してください。

### YouTube の OAuth

Codespace は非対話なのでブラウザが必要な認証は通せません。**ローカルマシンで**取得して持ち込みます。

1. Google Cloud Console → APIs & Services → Credentials で
   **OAuth client ID（種別: Desktop app）** を作成し JSON をダウンロード
2. `config/oauth/client_secret.json` に置く
3. ブラウザのあるマシンで `tube-auto auth --channel ja` を実行
4. 生成された `config/oauth/token_ja.json` をこの環境にコピー

`config/oauth/` は `.gitignore` 済みです。

### 投稿を始める前に

`config/settings.yaml` の `publish.channel_started_on` にチャンネル開設日を書いてください。
**未設定のあいだは保守的に1本/日に制限されます。**

開設から投稿開始までは2週間ほど空け、その間は普通に視聴・登録して履歴を作っておくこと。
視聴履歴のない新規アカウントがいきなり毎日投稿すると、スパムを疑われます。

## 使い方

```bash
tube-auto status                   # いま何がどの段階にいて、次に何をすべきか
tube-auto themes                   # テーマ一覧と各腕の現在の配分

tube-auto build                    # research → assemble を通しで1本
# ↑ を段階ごとに実行する場合:
tube-auto research                 #   題材を選び、一次ソースを3〜5本束ねて S1..Sn を振る
tube-auto script --idea 1          #   章立て台本。出典IDのない数値は差し戻される
tube-auto narrate --idea 1         #   Chirp 3 HD で2話者合成（月100万文字まで無料）
tube-auto footage --idea 1         #   NASA素材。利用条件5項目でフィルタ
tube-auto diagrams --idea 1        #   matplotlib のアニメーション図解
tube-auto assemble --idea 1        #   ffmpeg で合成

streamlit run review_app.py        # ← 人間の承認ゲート。ここを通らないと投稿されない
tube-auto publish                  # private でアップロード（ランプアップ表に従う）
tube-auto go-live                  # ← public に切り替える。これをやるまで再生されない
tube-auto sync-stats               # 24h/72h/7d の固定窓 + latest（毎回更新）で計測
tube-auto report                   # 4,000時間ゲートへの現在地と、続けるか止めるかの材料
tube-auto gc                       # どこからも参照されていない作業ファイルを削除
```

`--dry-run` は `research` / `script` / `publish` / `go-live` / `gc` で使えます。

## 設計上の要点

### 支出の上限はコードで強制する

`budget.py` が毎回の課金前に月次と実行ごとの上限を検査します。
月次の合計は**そのつどDBから読み直します**。プロセス内にキャッシュすると、
2つの実行がそれぞれ上限いっぱいまで使えてしまうためです。

台帳は**追記専用**（`llm_calls` / `generations`）で、成果物（`renders`）とは別テーブルです。
レビューUIの「作り直す」は `renders` を消しますが台帳には触りません。
**使った金は使ったままにしておかないと、上限が何も見ていないことになります。**

同時実行は `exclusive_run()` のロックで防ぎます。失敗しても解放されます。

### 素材構成 — 実映像は主役にできない

在庫を数えた結果です。

```
NASA 動画      7,559 件   ← 少ない。ブラックホール51件、超新星20件、重力波3件
NASA 静止画  166,793 件   ← 豊富
```

20分は1カット30秒換算で約40カット必要なので、理論系のテーマは動画在庫が即枯渇します。
そこで**静止画＋図解を主役、実映像はアクセント**に配分しました（`settings.yaml` の `video.composition`）。

図解はプログラム生成なので無限に作れます。理論系の弱点をここで埋めます。

**動画の使用はテーマごとのオプトイン**です（`allow_footage`）。現在 true は
`solar_system` と `space_history` の2つだけ。理由は次項です。

### メタデータはフレームの中身を説明しない

これがこのプロジェクトで一番高くついた学びです。

権利フィルタが読めるのはメタデータだけで、メタデータは**画面に何が写っているか**を
一言も語りません。実際に組み上げた動画を目視した結果、自動チェックを全部通過したうえで
**司会者・NASAのスレート・第三者クレジット**が焼き込まれていました。

対処は、ブラックリストを1行足すことではなく構造を変えることでした。

- 動画はテーマごとのオプトイン（既定はオフ）
- 理論系は静止画（166,793件、ほぼ単一画像）＋生成図解で組む
- ミッション系だけ動画を使う
- **人間のレビューを、ピクセルレベルの確認項目にする**

`review_app.py` の確認項目5つ（ロゴ・人物・第三者クレジット・出典との一致・読み間違い）は、
すべて実際に起きた事故に対応しています。承認にはその5つ全部にチェックが要ります。

### NASA素材の利用条件は5項目ある

NASAコンテンツは米国で著作権の対象外で商用利用できますが、無条件ではありません。
`nasa.py` が5項目を検査します。

| 条件 | 実装 |
|---|---|
| NASAの推奨を示唆しない | 「NASA公認」等を禁止語に。説明欄に非提携の一文 |
| 第三者著作物は対象外 | 著作権表記のあるメタデータを除外（`©` `(c)` も含む） |
| NASAロゴは対象外 | ロゴ・スレートが主体の素材を除外 |
| 人物の肖像権 | 人物が主体の素材を除外 |
| 出典明示 | 説明欄の**先頭付近**に `Images/Video: NASA` を固定 |

**Hubble（STScI/AURA）・ESA・JAXA は要許諾なので使いません。**
NASA本体とJWST（NASA配信分）に限定しています。

### 台本の事実性は「方針」ではなく「検査」

リサーチが集めた一次ソースに `S1` `S2` … のIDを振り、台本の各数値・主張に `[S2]` を付けさせます。
**出典IDのない検証可能な数値を含む台本は生成失敗として扱います**（`citations.py`）。

説明欄には出典URLを全部載せます。まとめ系がやらないことをやる、という差別化でもあります。

### 読み間違い対策は台本の段階で

日本語TTSは指数表記・単位記号・カタログ名を誤読します（`10^24 kg`、`ケプラー452b`）。
公式の対処はIPA指定ですが、目視でレビューできないので採用していません。

代わりに台本が**表示用（字幕）と読み上げ用（カナ開き）の2本**を持ちます。
差分は `config/terms.yaml` に置き、1本目の試聴で育てます（`reading.py`）。

### private のままでは何も測れない

`publish` は必ず `private` で上げます。`go-live` を実行するまで公開されません。
`went_public_at` が計測窓の起点です。アップロード時刻から測ると、
見えていなかった時間を「露出」として数えてしまいます。

`go-live` はさらに、YouTube側にAI開示が実際に記録されたかを読み戻して確認します。
insert のボディにフィールドを入れたことは、保存された証拠にはならないためです。

公開時にテーマごとのプレイリストへ自動で追加します。プレイリストの失敗は
**公開を巻き戻しません** — どこにも分類されていない公開動画のほうが、非公開よりましです。

### 投稿ペースはランプアップする

```yaml
publish:
  ramp_up:
    - { until_day: 14, per_week: 3 }   # 1〜2週目
    - { until_day: 28, per_week: 5 }   # 3〜4週目
    - { until_day: null, per_week: 7 } # 以降は毎日
```

2週で6本、4週で16本、12週で71本。4,000時間の到達は2.8ヶ月→3.5ヶ月に遅れますが、
凍結リスクを下げる方が期待値が高いという判断です。

API上限（10,000 units/日 ÷ videos.insert 1,600 units = 6本/日）も `hard_daily_cap` で二重に押さえます。

### 二重投稿は構造で防ぐ

`posts` は `UNIQUE(idea_id)`。アップロードは1本ごとに即コミットします。
アップロードは取り消せないので、記録を失うと同じ動画をもう一度上げることになり、
**再利用コンテンツ判定はチャンネル全体に及びます。**

### A/Bの単位はテーマ

7テーマ × 言語 = 腕。`scoring.py` の**不足ベースのサンプラー**が、
配分に対して最も遅れている腕を選びます。無状態のサンプラーは低シェアの腕を
永久に飢えさせるので、実績（`posts`）を毎回読み直します。

各腕が `min_samples_before_weighting` 本に達するまでは配分を均等にし、判定も出しません。

### AI生成であることの開示

アップロードは常に `status.containsSyntheticMedia = True` を立てます。
パラメータ化していません。厳密には不要な可能性が高い（架空のナビゲーターがNASAの実素材を
解説するだけ）のですが、**開示してもAIラベルが付くだけで収益化に影響しない**と明記されているので、
迷う理由がありません。

## テスト

```bash
pytest
```

112件。APIはモックせず呼びません。検証しているのは、**再現した欠陥それぞれに対する回帰**です。

- 作り直しで課金台帳が消えないこと / クラッシュしても記録が残ること
- 同じ企画が二度投稿されないこと（`UNIQUE(idea_id)` まで含めて）
- 権利未確認の素材があると投稿が止まること
- ランプアップ表どおりの本数に制限されること
- 計測の欠測が満点扱いにならないこと / 10日遅れの窓が「24h」に混ざらないこと
- 日本語の説明文がバイト長で切られること（1文字3バイト）
- 短い章にも図解が割り当たること / 同じ素材が7スロットを埋めないこと
- 動画を使わないテーマで、空いた枠が図解ではなく静止画に回ること
- 日本語の字幕が句点の前・開き括弧の後で改行されないこと
- 目次の先頭が `00:00` であること（そうでないとYouTubeが目次ごと無視する）
- プレイリストの失敗が公開を巻き戻さないこと
- 旧スキーマのDBにデータがあるとき、黙って移行せず拒否すること

## 構成

```
config/
  settings.yaml          予算・ランプアップ・素材配分・モデル・判定閾値
  channels.yaml          チャンネルとOAuthトークンの場所
  themes/*.yaml          テーマ定義（1ファイル1テーマ、7つ）
  terms.yaml             読み辞書。試聴して育てる
src/tube_auto/
  budget.py              月次/実行あたりの上限と排他ロック
  pricing.py             モデル別の単価とリクエスト検証
  citations.py           出典IDの検査
  reading.py             表示用/読み上げ用の変換と読み辞書
  brand.py               ナビゲーター・配色・章立て・定型句
  nasa.py                NASA API と利用条件5項目のフィルタ
  feeds.py               NASA/JPL RSS と arXiv
  dedup.py               重複排除の2層
  scoring.py             実績→腕への配分と抽選
  report.py              4,000時間ゲートへの現在地と撤退判断
  doctor.py              セットアップ診断
  ffmpeg.py              合成のプリミティブ
  tts.py                 Chirp 3 HD
  youtube.py             Data API / Analytics API / プレイリスト
  stages/                research / script / narrate / footage / diagrams /
                         assemble / publish / golive / analytics
review_app.py            Streamlit の承認ゲート
```

データモデルは**課金台帳と成果物を分離**しています。
`llm_calls`・`generations`（追記専用・削除不可）と `renders`（差し替え可能）を分けることで、
成果物を作り直しても支出の記録が消えません。

スキーマは `PRAGMA user_version` で管理し、**CREATE の前に**移行します。
`CREATE TABLE IF NOT EXISTS` は形の食い違いを黙って隠すためです。
古いバージョンのDBにデータが入っていた場合は移行せず拒否します
（8秒のショートを前提にしたデータを、ナレーション付き長尺に正直に対応づける方法はありません）。

## 正直な確率

ラッコM&Aの売却案件17件中12件が月3万円を超えていますが、これは**売れる状態の
チャンネルだけのサンプル**で分母が不明です。同じジャンルに収益ゼロの実例もあります。

**6ヶ月で月¥30,000到達: 30〜40%。12ヶ月: 50〜60%。**
下振れした場合の損失は累計 ¥15,000〜25,000 で止まります。
