# tube-auto

15〜20分の日本語・科学解説動画を自動で作って投稿するパイプライン。
一次ソース収集 → 台本 → ナレーション → 素材 → 図解 → 合成 → 人間レビュー → 投稿 → 公開 →
計測 → 実績を企画へ戻す、までを1本の CLI で回します。

> リポジトリ名は `Youtube-Shorts-Auto` のままですが、**ショートは作りません。**
> 理由は下の「なぜ長尺なのか」にあります。

## これは何を狙っているのか

**コストを差し引いて月30,000円。生成予算は月5,000円以内。**

最大の関門は再生数ではなく**収益化ゲート（直近12ヶ月で総再生時間4,000時間）**です。
実測から逆算すると1本あたり約47時間、つまり**約85本**。ランプアップを含めて約3.5ヶ月かかります。

### なぜ長尺なのか

ショートを捨てたのは好みの問題ではありません。

| | 長尺 | ショート |
|---|---|---|
| RPM（実測・日本の知的雑学） | **¥561.6** | ¥4.5〜15 |
| 粗収益¥35,000に必要な月間再生数 | 6〜12万回 | **233〜778万回** |
| 収益化ゲートへの寄与 | 総再生時間にカウント | **カウントされない** |

**ショートの視聴時間は4,000時間に一切カウントされません。**
同ジャンルの実在の失敗例は、32本中3割をショートに使い、有効再生時間1,500時間で収益ゼロ。
同ジャンルの成功例は91本すべて長尺で、登録者5,000人・月¥77,047。差はここでした。

### 撤退基準はコードに入っている

`tube-auto report` が判断材料を出します。勘で続けないための装置です。

| 時点 | 基準 | 満たさなければ |
|---|---|---|
| 1本目 | 全編試聴して「自分が見たいと思うか」 | 設計を見直す |
| 1ヶ月 | 累計16本 / 視聴維持率30%以上 / 実測RPM ¥150以上 | 台本・冒頭5秒・サムネを見直す |
| 3.5ヶ月 | 有効再生時間が4,000時間の50%以上 | **中止を検討** |
| 収益化後2ヶ月 | 月¥10,000以上 | 中止 |
| 随時 | 累計コスト ¥30,000 | 見直し |

`report` は**証拠が足りないうちは判定を出しません**。腕ごとのサンプルが
`min_samples_before_weighting` に届くまで「判定不能」と言い続けます。

## セットアップ

```bash
sudo apt-get install -y ffmpeg fonts-noto-cjk fonts-mplus   # 合成・CJK字幕・図の文字に必須
pip install -e ".[dev,review]"
cp .env.example .env                            # ANTHROPIC_API_KEY を記入
tube-auto init
tube-auto doctor                                # 何が足りないか一覧で出る
```

ナレーションは既定で **VOICEVOX（ずんだもん／四国めたん、ローカル・無料）** を使うので、
これだけならAPIキーもGoogle認証も要りません。VOICEVOXエンジンの用意は次の章。
Google Cloud TTSをフォールバックとして使う場合だけ、別途
`gcloud auth application-default login` が要ります（`config/settings.yaml` の `tts.provider: google`）。

`tube-auto doctor` は、ツール・APIキー・**VOICEVOXエンジンの疎通と話者ID**・OAuthトークン・
設定の整合・今月の支出・価格表の鮮度・NASA APIの到達性・止まっている工程を一度に診断します。
**キーを入れる前でも動く**ので、まずこれを実行してください。

## 初回セットアップ（Windows + WSL2 + VOICEVOX）

生成PC（RTX/RXどちらでもよい。VOICEVOXはCPU版を使うのでGPUの種類は関係ない）を
Windows上のWSL2で動かす場合の、PowerShellを開いた直後からの手順です。

### 1. WSL2のUbuntuに入る

PowerShellで:
```powershell
wsl
```
複数ディストリがある場合は `wsl -l -v` で名前を確認し `wsl -d Ubuntu` のように指定する。
`wsl` 自体が見つからないと出た場合、それは**すでにWSL内にいる**（プロンプトが
`user@HOST:~$` になっている）のに、もう一度呼び出そうとしている可能性が高い。
その場合はそのまま次に進んでよい。

### 2. リポジトリと依存パッケージ

```bash
cd ~
git clone <このリポジトリのURL> Youtube-Shorts-Auto   # 既にあれば git pull
cd Youtube-Shorts-Auto
sudo apt update && sudo apt install -y ffmpeg fonts-noto-cjk fonts-mplus p7zip-full curl unzip
pip install -e ".[dev,review]"
cp .env.example .env   # ANTHROPIC_API_KEY を記入
```

### 3. VOICEVOXエンジン（Linux・CPU版 x64）を用意する

**Windows版アプリではなく、Linux向けのビルドをWSL2内に置く。**
WSL2からWindows版アプリのポートへ繋ぐ方法もあるが、ファイアウォールで弾かれやすく、
Linux版を直接動かす方が確実。GPU版（NVIDIA/DirectML）は不要 ― CPU版で十分な速度が出る。

1. https://github.com/VOICEVOX/voicevox_engine/releases を開き、最新の安定版
   （`0.26.0-dev` のような prev/dev 版ではなく無印バージョン）を選ぶ。
2. Assets一覧から **`voicevox_engine-linux-cpu-x64-<version>.7z.001`** を探す。
   同名で `.7z.002` 以降が無ければ、この1ファイルで完結している。
   （`arm64` ではなく `x64`。Windows用やmacOS用、GPU版は使わない）
3. `gh` (GitHub CLI) が使えるなら一発で取れる:
   ```bash
   mkdir -p ~/voicevox_engine && cd ~/voicevox_engine
   gh release download <version> --repo VOICEVOX/voicevox_engine \
     --pattern "voicevox_engine-linux-cpu-x64-<version>.7z.001"
   ```
   使えない場合はブラウザでリンクをコピーして `curl -L -o voicevox_engine-linux-cpu-x64-<version>.7z.001 "<URL>"`。
4. 展開する。**必ずWSL(Linux)側のターミナルで実行する** ―
   Windowsのエクスプローラーや7-Zip GUIで `\\wsl.localhost\...` 越しに展開すると、
   同梱されているシンボリックリンク（`libscipy_openblas64_*.so` 等）が壊れる。
   ```bash
   7z x voicevox_engine-linux-cpu-x64-*.7z.001
   ```
5. `run` の場所を確認し、実行権限を付ける:
   ```bash
   find ~/voicevox_engine -name run
   chmod +x ~/voicevox_engine/linux-cpu-x64/run
   ```
   このパスが `config/settings.yaml` の `tts.voicevox.engine_dir`
   （既定値 `~/voicevox_engine/linux-cpu-x64`）と一致していれば設定変更は不要。
6. 起動確認（1回だけ手動で。以後は `tube-auto narrate` が自動起動・自動終了する）:
   ```bash
   cd ~/voicevox_engine/linux-cpu-x64
   ./run --host 127.0.0.1 --port 50021
   ```
   初回はモデル読み込みで数十秒〜数分かかる。別ウィンドウで:
   ```bash
   curl http://127.0.0.1:50021/version
   curl -s http://127.0.0.1:50021/speakers | \
     python3 -c "import json,sys; [print(s['name'],[(st['name'],st['id']) for st in s['styles']]) for s in json.load(sys.stdin) if s['name'] in ('ずんだもん','四国めたん')]"
   ```
   `ずんだもん` にID 3、`四国めたん` にID 2の「ノーマル」があれば成功。確認できたら
   `Ctrl+C` で止めてよい。

### 4. 診断

```bash
tube-auto doctor
```
`VOICEVOX` の行が `OK` になっていれば準備完了。`sprites`（立ち絵）の `WARN` は
素材未設置のあいだ出続けるが、無くても動画は作れる（丸いプレースホルダで代用される）。

### 日々の起動（2回目以降）

```powershell
wsl
```
```bash
cd ~/Youtube-Shorts-Auto
git pull
tube-auto status
```
VOICEVOXエンジンは手動起動しなくてよい。`tts.voicevox.engine_dir` が設定済みなら
`tube-auto narrate` の実行時に自動で起動し、終了時に自動で止まる。

### YouTube の OAuth

Codespace は非対話なのでブラウザが必要な認証は通せません。**ローカルマシンで**取得して持ち込みます。

1. Google Cloud Console → APIs & Services → Credentials で
   **OAuth client ID（種別: Desktop app）** を作成し JSON をダウンロード
2. `config/oauth/client_secret.json` に置く
3. ブラウザのあるマシンで `tube-auto auth --channel ja` を実行
4. 生成された `config/oauth/token_ja.json` をこの環境にコピー

`config/oauth/` は `.gitignore` 済みです。

### 投稿を始める前に

`config/settings.yaml` の `publish.channel_started_on` にチャンネル開設日を書いてください。
**未設定のあいだは保守的に1本/日に制限されます。**

開設から投稿開始までは2週間ほど空け、その間は普通に視聴・登録して履歴を作っておくこと。
視聴履歴のない新規アカウントがいきなり毎日投稿すると、スパムを疑われます。

## 使い方

```bash
tube-auto status                   # いま何がどの段階にいて、次に何をすべきか
tube-auto themes                   # テーマ一覧と各腕の現在の配分

tube-auto build                    # research → assemble を通しで1本
# ↑ を段階ごとに実行する場合:
tube-auto research                 #   題材を選び、一次ソースを3〜5本束ねて S1..Sn を振る
tube-auto script --idea 1          #   章立て台本。出典IDのない数値は差し戻される
tube-auto narrate --idea 1         #   VOICEVOX（ずんだもん/四国めたん）で2話者合成。無料
tube-auto footage --idea 1         #   NASA静止画。章の背景に薄く敷く分だけ。利用条件5項目でフィルタ
tube-auto assemble --idea 1        #   板書を行ごとに描画し、音声と合成（サムネイル3案もここで出る）
tube-auto thumbnails --idea 1      #   サムネイルだけ作り直す

streamlit run review_app.py        # ← 人間の承認ゲート。ここを通らないと投稿されない
tube-auto publish                  # private でアップロード（ランプアップ表に従う）
tube-auto go-live                  # ← public に切り替える。これをやるまで再生されない
tube-auto sync-stats               # 24h/72h/7d の固定窓 + latest（毎回更新）で計測
tube-auto ab --idea 1 --winner question   # Studio の Test & Compare の結果を手入力
tube-auto report                   # 4,000時間ゲートへの現在地と、続けるか止めるかの材料
tube-auto gc                       # どこからも参照されていない作業ファイルを削除
```

`--dry-run` は `research` / `script` / `publish` / `go-live` / `gc` で使えます。

## 設計上の要点

### 支出の上限はコードで強制する

`budget.py` が毎回の課金前に月次と実行ごとの上限を検査します。
月次の合計は**そのつどDBから読み直します**。プロセス内にキャッシュすると、
2つの実行がそれぞれ上限いっぱいまで使えてしまうためです。

台帳は**追記専用**（`llm_calls` / `generations`）で、成果物（`renders`）とは別テーブルです。
レビューUIの「作り直す」は `renders` を消しますが台帳には触りません。
**使った金は使ったままにしておかないと、上限が何も見ていないことになります。**

同時実行は `exclusive_run()` のロックで防ぎます。失敗しても解放されます。

概念図を切った状態で **1本 約¥43、月30本で約¥1,290**。予算¥5,000に対して十分な余裕があります。

### 概念図をどこまで足せるか

このパイプラインで**使った分だけ費用が増えるのはここだけ**です。既定はオフ。

| 1本あたり | 月30本 | 台本と合わせて | 上限$33に対して |
|---|---|---|---|
| 0枚（既定） | $0 | $8.55 | 26% |
| 6枚 | $7.0 | $15.6 | 47% |
| 20枚 | $23.4 | $31.9 | **97%** ← 事故ると即上限 |

`tube-auto doctor` が「6/video at $0.039 = $7.02/month of the $33.00 cap」と現在の設定で
月いくらになるかを先に出します。上限の75%を超える設定は警告になります。

有効にするには `GEMINI_API_KEY` を `.env` に入れて `images.enabled: true`。
キーが無ければ自動的にオフになり、matplotlib の図解だけで組み上がります。

### 素材構成 — 実映像は主役にできない

在庫を数えた結果です。

```
NASA 動画      7,559 件   ← 少ない。ブラックホール51件、超新星20件、重力波3件
NASA 静止画  166,793 件   ← 豊富
```

20分は1カット30秒換算で約40カット必要なので、理論系のテーマは動画在庫が即枯渇します。
そこで**静止画＋図解を主役、実映像はアクセント**に配分しました（`settings.yaml` の `video.composition`）。

図解はプログラム生成なので無限に作れます。理論系の弱点をここで埋めます。

**動画の使用はテーマごとのオプトイン**です（`allow_footage`）。現在 true は
`solar_system` と `space_history` の2つだけ。理由は次項です。

### メタデータはフレームの中身を説明しない

これがこのプロジェクトで一番高くついた学びです。

権利フィルタが読めるのはメタデータだけで、メタデータは**画面に何が写っているか**を
一言も語りません。実際に組み上げた動画を目視した結果、自動チェックを全部通過したうえで
**司会者・NASAのスレート・第三者クレジット**が焼き込まれていました。

対処は、ブラックリストを1行足すことではなく構造を変えることでした。

- 動画はテーマごとのオプトイン（既定はオフ）
- 理論系は静止画（166,793件、ほぼ単一画像）＋生成図解で組む
- ミッション系だけ動画を使う
- **人間のレビューを、ピクセルレベルの確認項目にする**

`review_app.py` の確認項目5つ（ロゴ・人物・第三者クレジット・出典との一致・読み間違い）は、
すべて実際に起きた事故に対応しています。承認にはその5つ全部にチェックが要ります。

### NASA素材の利用条件は5項目ある

NASAコンテンツは米国で著作権の対象外で商用利用できますが、無条件ではありません。
`nasa.py` が5項目を検査します。

| 条件 | 実装 |
|---|---|
| NASAの推奨を示唆しない | 「NASA公認」等を禁止語に。説明欄に非提携の一文 |
| 第三者著作物は対象外 | 著作権表記のあるメタデータを除外（`©` `(c)` も含む） |
| NASAロゴは対象外 | ロゴ・スレートが主体の素材を除外 |
| 人物の肖像権 | 人物が主体の素材を除外 |
| 出典明示 | 説明欄の**先頭付近**に `Images/Video: NASA` を固定 |

**Hubble（STScI/AURA）・ESA・JAXA は要許諾なので使いません。**
NASA本体とJWST（NASA配信分）に限定しています。

### サムネイルは「小さい絵」ではない

サムネイルが選ばれるのはモバイルのフィード上、**約210×118ピクセル**です。その大きさでは
20文字の日本語は灰色のシミにしかなりません。だから設計の出発点は「絵を作る」ではなく
**「9文字前後を、限界まで大きく」**です。他はすべてそこから決まります。

背景はその回のNASA静止画を使います。生成イラストではありません。理由は3つ。
すでにダウンロード済みで権利確認も済んでいるので**追加費用も新しい権利問題も発生しない**、
本物の観測画像はまとめ系が持っていないもの、そして生成カバーアートは
YouTubeの inauthentic content ルールがまさに見ているものだからです。

3案は**主張が違います**。同じ絵の別トリミングではありません。

| 案 | 何を出すか | 例 |
|---|---|---|
| `number` | 台本で最大の数値 + 小さな主題ラベル | ブラックホール／**1200万キロ** |
| `question` | 冒頭フックの問い | **本当に「穴」？** |
| `subject` | 主題そのもの | **ブラックホールの常識が変わった話** |

Test & Compare は勝者を教えますが理由は教えないので、**あとから読み解ける形で**変えてあります。
フォントだけ変えた3案では、勝っても何も学べません。

1枚目が投稿時に付き、残り2枚は Studio で A/B にかけます（APIがないので手作業30秒）。
結果は `tube-auto ab --idea 1 --winner question` で戻します。これが唯一、結果が
パイプラインに帰ってくる経路です。`report` が案ごとの勝率を出します（5件を超えるまでは
「傾向とは言えません」と付記されます）。

### 音は章に合わせて変わり、声の下に沈む

**1曲を18分ループさせるのは、自動生成チャンネルの一番わかりやすい音の痕跡**です。
2分の曲なら9回繰り返し、耳は3回目あたりで気づきます。対処は3つあり、3つとも要ります。

| | やること | なぜ |
|---|---|---|
| **章ごとに曲を変える** | 7章それぞれに別の曲 | 構成が既にあるのに、音楽だけそれを無視していた |
| **章の継ぎ目で無音にする** | 各章の頭と尻でフェード | 章タイトル画面と重なり、**目で見えた区切りが耳でも聞こえる** |
| **ダッキング** | ナレーションをキーにサイドチェイン圧縮 | 固定音量は、声の下でうるさいか、間で聞こえないかのどちらかにしかならない |

曲の選択は**決定的**です。レビューで却下して作り直しても、同じ曲で組み上がります。
隣り合う章が同じ曲になることもありません。

### ダッキングの数値は測って決めた

| 設定 | ダッキング量 | 判定 |
|---|---|---|
| threshold 0.05 / ratio 6 | 3.6 dB | 浅い。BGMが声と張り合う |
| **threshold 0.03 / ratio 8** | **7.7 dB** | **採用**（放送で音楽を声の下に敷く標準域は6〜10 dB） |
| threshold 0.02 / ratio 12 | 11.3 dB | 深すぎ。BGMが「引く」ではなく「消える」 |

測定は、ナレーションをキーにしただけの**BGM単体**に対して行いました。混ぜたまま測ると
声が24 dB上に乗っていてBGMの動きが見えません（最初その測り方をして「効いていない」と読み違えました）。

### 音楽の置き場所

YouTube オーディオライブラリはログインが必要でAPIが無いため、**ここだけは手作業**です。

```
work/bgm/tension/     つかみ
work/bgm/wonder/      今日の話・本題
work/bgm/calm/        前提・詳しく
work/bgm/reflective/  何が覆ったか
work/bgm/resolve/     まとめ
```

各2〜3曲で足ります。サブフォルダを作らず `work/bgm/` 直下に置いても動きます（全章で同じ候補群）。
1曲も無ければBGM無しで組み上がります。`tube-auto doctor` が状態を出します。

### タイトルは5秒後に出る

冒頭5秒は**測定でパターン・インタラプトの窓**と分かっている場所です。そこにロゴを置くのは、
動画で唯一全員が見る部分を、まだ誰も興味を持つ理由のないブランディングに使うことになります。

だからオープニングの前口上はありません。タイトルテロップは**5.0秒から4.5秒間**、
フェードイン・アウトで本編の映像に重なります。

終了画面はAPIが無いので、最後の11秒に**クロージングカードを焼き込み**ます。
ナレーションは同じ長さだけ無音で延長されます（そうしないと `-shortest` が最後の一言で切ります）。

### 生成した概念図には「文字を書かせない」

`imagegen.py` のプロンプトには、呼び出し側から変えられない制約が焼き込んであります。

- **文字・数字・キャプションを描かせない** — 生成された文字はほぼ崩れ、崩れた文字が
  画面に出ることは自動生成チャンネルの一番わかりやすい印だからです
- **ロゴ・記章・人物を描かせない** — NASA素材でやった権利の作業が、生成フレームで
  同じものを持ち込んだら無意味になります

生成した画像は**動画に使う前にデコードできるか確認**します。壊れた画像を `-loop 1` で
渡されたffmpegは壊れたフレームを無限に読み直し、5分後にタイムアウトで殺されるまで止まりません。

図解1枚が失敗しても動画は落ちません。matplotlib の図解に差し替わり、
課金は発生していないので台帳にも何も残りません。予算上限に当たった場合も同じです。

### 台本の事実性は「方針」ではなく「検査」

リサーチが集めた一次ソースに `S1` `S2` … のIDを振り、台本の各数値・主張に `[S2]` を付けさせます。
**出典IDのない検証可能な数値を含む台本は生成失敗として扱います**（`citations.py`）。

説明欄には出典URLを全部載せます。まとめ系がやらないことをやる、という差別化でもあります。

### 読み間違い対策は台本の段階で

日本語TTSは指数表記・単位記号・カタログ名を誤読します（`10^24 kg`、`ケプラー452b`）。
公式の対処はIPA指定ですが、目視でレビューできないので採用していません。

代わりに台本が**表示用（字幕）と読み上げ用（カナ開き）の2本**を持ちます。
差分は `config/terms.yaml` に置き、1本目の試聴で育てます（`reading.py`）。

### private のままでは何も測れない

`publish` は必ず `private` で上げます。`go-live` を実行するまで公開されません。
`went_public_at` が計測窓の起点です。アップロード時刻から測ると、
見えていなかった時間を「露出」として数えてしまいます。

`go-live` はさらに、YouTube側にAI開示が実際に記録されたかを読み戻して確認します。
insert のボディにフィールドを入れたことは、保存された証拠にはならないためです。

公開時にテーマごとのプレイリストへ自動で追加します。プレイリストの失敗は
**公開を巻き戻しません** — どこにも分類されていない公開動画のほうが、非公開よりましです。

### 投稿ペースはランプアップする

```yaml
publish:
  ramp_up:
    - { until_day: 14, per_week: 3 }   # 1〜2週目
    - { until_day: 28, per_week: 5 }   # 3〜4週目
    - { until_day: null, per_week: 7 } # 以降は毎日
```

2週で6本、4週で16本、12週で71本。4,000時間の到達は2.8ヶ月→3.5ヶ月に遅れますが、
凍結リスクを下げる方が期待値が高いという判断です。

API上限（10,000 units/日 ÷ videos.insert 1,600 units = 6本/日）も `hard_daily_cap` で二重に押さえます。

### 二重投稿は構造で防ぐ

`posts` は `UNIQUE(idea_id)`。アップロードは1本ごとに即コミットします。
アップロードは取り消せないので、記録を失うと同じ動画をもう一度上げることになり、
**再利用コンテンツ判定はチャンネル全体に及びます。**

### A/Bの単位はテーマ

7テーマ × 言語 = 腕。`scoring.py` の**不足ベースのサンプラー**が、
配分に対して最も遅れている腕を選びます。無状態のサンプラーは低シェアの腕を
永久に飢えさせるので、実績（`posts`）を毎回読み直します。

各腕が `min_samples_before_weighting` 本に達するまでは配分を均等にし、判定も出しません。

### 自動化するのは計測だけ

| ワークフロー | 起動 | 理由 |
|---|---|---|
| `daily.yml` | **手動のみ** | 課金が発生し、人間の承認が要るものを作る |
| `measure.yml` | **毎日 07:00 JST** | 読むだけ。レビューするものが無い |

投稿と公開は自動化しません。人間のレビューと Studio での確認こそが、YouTubeの2025年
ポリシーが求める「編集上の関与」そのものだからです。無人でアップロードしたら、
その関与を自分で消すことになります。

計測の方は逆に、**サボると取り返しがつきません。** 計測窓は24h/72h/7dで、窓の外で
撮ったスナップショットは埋め合わせされず「欠測」として記録されます。10日分の再生数を
「24h」として記録したらテーマ間の比較が壊れるからです。欠測が続けばA/Bに判定材料が
残らず、このパイプラインの存在理由が消えます。

### AI生成であることの開示

アップロードは常に `status.containsSyntheticMedia = True` を立てます。
パラメータ化していません。厳密には不要な可能性が高い（架空のナビゲーターがNASAの実素材を
解説するだけ）のですが、**開示してもAIラベルが付くだけで収益化に影響しない**と明記されているので、
迷う理由がありません。

## テスト

```bash
pytest
```

170件。APIはモックせず呼びません。検証しているのは、**再現した欠陥それぞれに対する回帰**です。

- 作り直しで課金台帳が消えないこと / クラッシュしても記録が残ること
- 同じ企画が二度投稿されないこと（`UNIQUE(idea_id)` まで含めて）
- 権利未確認の素材があると投稿が止まること
- ランプアップ表どおりの本数に制限されること
- 計測の欠測が満点扱いにならないこと / 10日遅れの窓が「24h」に混ざらないこと
- 日本語の説明文がバイト長で切られること（1文字3バイト）
- 短い章にも図解が割り当たること / 同じ素材が7スロットを埋めないこと
- 動画を使わないテーマで、空いた枠が図解ではなく静止画に回ること
- 日本語の字幕が句点の前・開き括弧の後で改行されないこと
- 目次の先頭が `00:00` であること（そうでないとYouTubeが目次ごと無視する）
- プレイリストの失敗が公開を巻き戻さないこと
- 組み上がった動画がレビュー待ち行列に載ること（載らず、承認が永久にできなかった）
- サムネイルの各行が読める長さを超えないこと
- 「3000分の1」が「3000分」という事実として拡大されないこと
- 「系外惑星」が「系／外惑星」で改行されないこと
- 権利未確認の静止画がサムネイル背景に使われないこと
- 出典検査に落ち続ける企画が、上限回数で課金を止められること
- 概念図の失敗・予算超過が、動画を落とさず図解に差し替わること
- 値段の付いていない画像モデルが「無料」ではなくエラーになること
- BGMが章ごとに変わり、隣り合う章で同じ曲にならないこと
- 作り直しても同じ曲で組み上がること
- 音楽ベッドの長さが動画とぴったり一致すること（`-ss` と `-stream_loop` の併用で13秒が25秒になっていた）
- BGMを足してもナレーションが6dB下がらないこと（amix の既定の正規化）
- クロージングカードの分だけ音声が延長されること
- 旧スキーマのDBにデータがあるとき、黙って移行せず拒否すること

## 構成

```
.github/workflows/
  daily.yml              1本作るところまで（手動起動。投稿は自動化しない）
  measure.yml            毎日の sync-stats（唯一のスケジュール実行）
config/
  settings.yaml          予算・ランプアップ・素材配分・モデル・判定閾値
  channels.yaml          チャンネルとOAuthトークンの場所
  themes/*.yaml          テーマ定義（1ファイル1テーマ、7つ）
  terms.yaml             読み辞書。試聴して育てる
  brand.yaml.example     チャンネル名・ナビゲーター・音声・配色の雛形
src/tube_auto/
  budget.py              月次/実行あたりの上限と排他ロック
  pricing.py             LLMと画像生成の単価
  imagegen.py            概念図の生成（文字・ロゴ・人物を禁じたプロンプト）
  citations.py           出典IDの検査
  reading.py             表示用/読み上げ用の変換と読み辞書
  brand.py               ナビゲーター・配色・章立て・定型句
  nasa.py                NASA API と利用条件5項目のフィルタ
  feeds.py               NASA/JPL RSS と arXiv
  dedup.py               重複排除の2層
  scoring.py             実績→腕への配分と抽選
  report.py              4,000時間ゲートへの現在地と撤退判断
  doctor.py              セットアップ診断
  ffmpeg.py              合成のプリミティブ
  bgm.py                 章ごとの音楽とダッキング
  tts.py                 Chirp 3 HD
  youtube.py             Data API / Analytics API / プレイリスト
  stages/                research / script / narrate / footage / diagrams /
                         assemble / thumbnails / publish / golive / analytics
review_app.py            Streamlit の承認ゲート
```

データモデルは**課金台帳と成果物を分離**しています。
`llm_calls`・`generations`（追記専用・削除不可）と `renders`（差し替え可能）を分けることで、
成果物を作り直しても支出の記録が消えません。

スキーマは `PRAGMA user_version` で管理し、**CREATE の前に**移行します。
`CREATE TABLE IF NOT EXISTS` は形の食い違いを黙って隠すためです。
古いバージョンのDBにデータが入っていた場合は移行せず拒否します
（8秒のショートを前提にしたデータを、ナレーション付き長尺に正直に対応づける方法はありません）。

## 正直な確率

ラッコM&Aの売却案件17件中12件が月3万円を超えていますが、これは**売れる状態の
チャンネルだけのサンプル**で分母が不明です。同じジャンルに収益ゼロの実例もあります。

**6ヶ月で月¥30,000到達: 30〜40%。12ヶ月: 50〜60%。**
下振れした場合の損失は累計 ¥15,000〜25,000 で止まります。
